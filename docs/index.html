The line · five stops

Every stop is one keystroke of context you don't have to carry.

Loopline reads the ticket key out of your branch name and back again, so each step already knows what the last one decided.

01 — Ticket

Start from the sprint, not a blank branch name.

A dedicated sidebar lists your active-sprint Jira tickets, grouped by status, with the ones that already have a local branch marked on branch. Click a ticket to open it in a themed panel styled after Jira's own issue view — summary, status chip, assignee, description — no browser needed. One toggle switches the scope to all open tickets.

02 — Branch

One ticket key becomes a correct branch.

Loopline maps the issue type to a prefix, slugifies the title, and lets you confirm or edit before it checks out bugfix/LPB-1234-some-summary-issue. It can fetch the base branch from origin first so you start from current code, and if a branch already exists for that ticket it stops and offers to switch — instead of silently landing you on the wrong one.

03 — Commit

The branch name writes the commit.

It parses the key and type back out of the branch and builds feat: LPB-1234 some summary issue. Staging respects your intent — if you've staged files, or individual hunks with git add -p, it commits exactly that; if nothing is staged it asks before pulling in untracked files. Re-run it and it offers to squash to one commit per MR with --force-with-lease.

04 — Push

Pushed with upstream tracking, checked for duplicates.

Loopline pushes the branch with tracking set, then checks for an existing open merge request for it before doing anything else — so re-running the command updates the loop instead of opening a second MR.

05 — Merge request

Open the MR with a description worth reading.

Optionally, Loopline drafts a real MR body from the branch diff and the ticket — summary, notable changes, the why, testing notes — and opens it in an editor for you to edit first. It can move the Jira ticket to In Review as the MR opens, and drop a dated bullet into an existing CHANGELOG.md. AI is off by default and points wherever you tell it to.

Off the main line

The parts of the day that aren't a straight run.

Status bar

Always-on ticket indicator

On a convention-named branch, the status bar shows the ticket. Click it to open the Jira issue or the merge request, copy the key, or jump into the next step. Updates when you switch branches from the terminal.

Standup

Summary from real commits

Reads today's commits across your local branches, groups them by the ticket key already in each message, and opens a copy-ready draft. Grounded only in commits that actually happened.

Impact

Time-saved footer

12 branches · 8 commits · 5 MRs · ~3.5h saved. Hidden until there's something to show, with the estimate's assumptions always in view.

Teams

Shared .loopline.json

Scaffold a committed config so everyone shares branch and commit conventions. An explicit personal setting always wins; secrets and tokens stay personal.

Networks

Corporate proxy & CA diagnostics

A one-command report covers proxy, CA certs, DNS, and a live API call with the exact failure code — for self-hosted Jira and GitLab behind a proxy or TLS inspection.

Privacy

AI is opt-in, and yours

Both AI features ship disabled. Enabled, they send your diff and ticket text to the Anthropic API — or to your company's compatible gateway. The key lives in VS Code Secret Storage.
